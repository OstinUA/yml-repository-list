# 📚 Repository List

**One file. Every repository. Always up to date.**

A GitHub Actions workflow that collects every public, non‑archived repository you own or co‑own
into a single tidy `REPOSITORYLIST.md`, grouped by owner — and commits it back to the repository,
on demand, with a single click.

## What it does

The workflow talks to the GitHub REST API through the [`gh` CLI](https://cli.github.com/), walks
through **every page** of `/user/repos`, keeps only the repositories you actually want, sorts them,
and writes the result to `REPOSITORYLIST.md`:

1. **Fetches** all repositories available to your token (personal **and** organization repositories).
2. **Filters** them — private, archived, disabled and explicitly excluded repositories are dropped.
3. **Sorts** them case‑insensitively by owner, then by repository name.
4. **Groups** them by owner, with exactly one blank line between groups.
5. **Commits** the file back to the repository — but only when something actually changed.

It is **manual by design** — no schedules, no surprise commits. Press *Run workflow* whenever you
want a fresh list (and see [Recipes](#recipes) if you ever want to put it on a cron).

## Output preview

```text
<!-- Auto-generated by .github/workflows/repository-list.yml. Do not edit manually. -->

# Repository List

**8** repositories · **3** owners

another-org/alpha

FCTostin-team/market-code_generator
FCTostin-team/progress-bar_display-panel
FCTostin-team/solar-accumulator-calculator

OstinUA/profile-readme
OstinUA/yml-repository-list
```

In the raw file every repository sits on its own line and a **blank line separates the
organizations**. Need clickable links or bullet points instead? Switch `OUTPUT_FORMAT` — see
[output formats](#output-formats).

> **Rendering note** — plain Markdown joins consecutive lines into one paragraph, so GitHub would
> show the list as a single wrapped block. That is why `plain` mode appends two trailing spaces to
> every line (a Markdown hard line break). Set `HARD_LINE_BREAKS: "false"` if you want byte‑clean
> lines for copy‑pasting, or use the `links` / `bullets` format for a fully native Markdown list.

## Features

| | Feature |
| :-- | :-- |
| 🔍 | **Complete coverage** — paginates through *all* repositories, no 100‑item API limit surprises |
| 🧹 | **Smart filtering** — skips private, archived, disabled, forked (optional) and self‑excluded repos |
| 🗂️ | **Owner grouping** — one blank line between organizations, alphabetical inside each group |
| 🎨 | **Three output formats** — plain text, bullet list, or clickable Markdown links |
| ⏱️ | **Fully idempotent** — no commit is made when the list has not changed (no timestamp noise) |
| ✋ | **Manual by default** — runs only when you press *Run workflow*; no crons, no surprise commits |
| 🎛️ | **Run-time switches** — `dry_run`, `include_forks` and `include_archived` inputs for one-off runs |
| 🧾 | **Run summary** — repository/owner counts plus a preview in the Actions summary tab |
| 🔐 | **Least privilege** — `contents: write` only, token passed through secrets, never logged |
| 🚦 | **Concurrency safe** — two runs can never race on the same file |
| 🧰 | **Zero dependencies** — pure `awk`, `sort` and the pre‑installed `gh` CLI |

## Quick start

1. **Fork or clone this repository** (or copy `.github/workflows/repository-list.yml` into your own repo).
2. **Create a personal access token** — see [Creating the token](#creating-the-token).
3. **Add it as a secret**: `Settings → Secrets and variables → Actions → New repository secret`
   - Name: `REPOSITORY_LIST_TOKEN`
   - Value: the token you just created
4. **Allow workflows to write**: `Settings → Actions → General → Workflow permissions →
   Read and write permissions → Save`.
5. **Run it**: `Actions → Repository List → Run workflow`. Leave *dry run* off and press the green
   button. `REPOSITORYLIST.md` appears in your repository a few seconds later. 🎉

That is it — re-run the workflow whenever you want the list refreshed.

## Creating the token

`secrets.GITHUB_TOKEN` **cannot** be used here: it is scoped to the single repository the workflow
runs in and cannot list your other repositories. A personal access token is required.

<details open>
<summary><b>Option A — classic token (simplest)</b></summary>

1. Go to <https://github.com/settings/tokens> → **Generate new token (classic)**.
2. Name it something like `repository-list-bot`, give it a long expiration date.
3. Select scopes:
   - `public_repo` — read public repositories (and push to this public repo);
   - `repo` — **only** if you want private repositories listed too;
   - `read:org` — recommended, so organization repositories are resolved reliably.
4. Generate, copy the value, and store it as the `REPOSITORY_LIST_TOKEN` secret.
</details>

<details>
<summary><b>Option B — fine-grained token (most secure)</b></summary>

1. Go to <https://github.com/settings/personal-access-tokens/new>.
2. **Repository access** → *All repositories* (needed to discover your repositories).
3. **Repository permissions**:
   - `Metadata: Read-only` — required to list repositories;
   - `Contents: Read and write` — required to push `REPOSITORYLIST.md` (grant it on **this**
     repository only, via *Only select repositories* + *All repositories* for Metadata).
4. For organizations, an organization owner may have to approve the token
   (`Organization settings → Personal access tokens → Pending requests`).
5. Generate, copy the value, and store it as the `REPOSITORY_LIST_TOKEN` secret.
</details>

## Configuration

### Workflow variables

Everything lives in the `env:` block at the top of
[`.github/workflows/repository-list.yml`](.github/workflows/repository-list.yml) — no other file
needs to be touched.

| Variable | Default | Description |
| :-- | :-- | :-- |
| `OUTPUT_FILE` | `REPOSITORYLIST.md` | Path of the generated file. Any name works (`REPOS.md`, `docs/LIST.md`, …). |
| `OUTPUT_FORMAT` | `plain` | `plain`, `bullets` or `links`. See [output formats](#output-formats). |
| `HARD_LINE_BREAKS` | `"true"` | In `plain` mode, append two spaces per line so Markdown renders one repository per line. Set `"false"` for byte‑clean output. |
| `INCLUDE_TIMESTAMP` | `"false"` | Adds `· last updated 2026-01-01 03:17 UTC` to the header. Turning it on means the file changes on **every** run. |
| `INCLUDE_PRIVATE` | `"false"` | Include private repositories. Requires the `repo` scope (classic) or `Metadata: Read` on private repos (fine‑grained). |
| `INCLUDE_ARCHIVED` | `"false"` | Include archived repositories (public *and* private archives). |
| `INCLUDE_FORKS` | `"true"` | Include forked repositories. Set `"false"` to keep only your own work. |
| `EXCLUDE_REPOS` | `".github"` | Comma‑separated names (`docs`) or slugs (`owner/docs`) to skip. Spaces are ignored. Leave empty to skip nothing. |
| `AFFILIATION` | `"owner,organization_member"` | Comma‑separated affiliations passed to the API: `owner`, `organization_member`, `collaborator`. |
| `REPOSITORY_LIST_TOKEN` secret | — | Personal access token used for both the API calls and the push. Required. |

Repositories with the **Disabled** flag are always skipped — they are not readable through the API.

### Manual run inputs

`Actions → Repository List → Run workflow` exposes three switches for one‑off runs. They override
the `env:` defaults for that single run and never modify the file.

| Input | Default | Description |
| :-- | :-- | :-- |
| `dry_run` | `false` | Build the file locally and print the summary, but **do not** commit or push. Handy for testing configuration changes. |
| `include_forks` | `true` | Same as `INCLUDE_FORKS`, for this run only. |
| `include_archived` | `false` | Same as `INCLUDE_ARCHIVED`, for this run only. |

## How it works

```text
        ┌──────────────────────────┐
        │  workflow_dispatch       │  │
        │  (manual "Run workflow") │  │
        └──────────────────────────┘  │
                                      ▼
                       ┌───────────────────────────────┐
                       │ gh api user/repos --paginate  │
                       │ → TSV: owner, name, fork,     │
                       │        archived, private,     │
                       │        disabled               │
                       └───────────────┬───────────────┘
                                       ▼
                       ┌───────────────────────────────┐
                       │ awk filters (private, archived│
                       │ disabled, forks, EXCLUDE_REPOS)│
                       └───────────────┬───────────────┘
                                       ▼
                       ┌───────────────────────────────┐
                       │ sort -f -u -t/ -k1,1 -k2,2    │
                       │ case-insensitive, deduplicated│
                       └───────────────┬───────────────┘
                                       ▼
                       ┌───────────────────────────────┐
                       │ awk renders owner/name lines, │
                       │ blank line per new owner      │
                       └───────────────┬───────────────┘
                                       ▼
                       ┌───────────────────────────────┐
                       │ REPOSITORYLIST.md + header    │
                       │ → git commit (only if changed)│
                       └───────────────────────────────┘
```

Each step of the workflow:

| Step | Purpose |
| :-- | :-- |
| **Check the token is configured** | Fails fast with a friendly error if the secret is missing — before anything else runs. |
| **Checkout repository** | Clones the repository with your PAT so the bot can push later. |
| **Fetch repositories** | Paginates the API, filters, sorts, groups and renders the Markdown file. Writes `total` / `owners` outputs. |
| **Summarise the run** | Builds a small table and a preview in the Actions run summary. |
| **Commit and push** | Commits as `github-actions[bot]` — or exits quietly when nothing changed / on a dry run. |

## Recipes

<details>
<summary><b>Refresh automatically on a schedule</b></summary>

The workflow ships manual-only. To also refresh it on a cron, add a `schedule` trigger next to
`workflow_dispatch`:

```yaml
on:
  schedule:
    - cron: "0 3 * * 0"      # every Sunday at 03:00 UTC
  workflow_dispatch:
```
</details>

<details>
<summary><b>Also list private repositories</b></summary>

```yaml
env:
  INCLUDE_PRIVATE: "true"
```

Remember to grant the token access to private repositories (`repo` scope, or fine‑grained
`Metadata: Read` + those repositories selected).
</details>

<details>
<summary><b>Hide forks and archived repositories</b></summary>

```yaml
env:
  INCLUDE_FORKS: "false"
  INCLUDE_ARCHIVED: "false"
```
</details>

<details>
<summary><b>Only my personal repositories, no organizations</b></summary>

```yaml
env:
  AFFILIATION: "owner"
```
</details>

<details>
<summary><b>Nicer Markdown with clickable links</b></summary>

```yaml
env:
  OUTPUT_FORMAT: links
  HARD_LINE_BREAKS: "false"   # irrelevant in links mode
```
</details>

<details>
<summary><b>Write into a subfolder and mirror it in the profile README</b></summary>

```yaml
env:
  OUTPUT_FILE: docs/REPOSITORYLIST.md
```

Missing folders are created automatically. Reference the file from your profile README:
`[All my repositories](docs/REPOSITORYLIST.md)`.
</details>

<details>
<summary><b>Keep a timestamp in the header</b></summary>

```yaml
env:
  INCLUDE_TIMESTAMP: "true"
```

The file will then be committed on every run, even when the list itself is unchanged.
</details>

## Running it locally

You only need the `gh` CLI and an authenticated token — the same logic runs in one pipeline:

```bash
export GH_TOKEN=ghp_xxxxxxxxxxxxxxxxxxxx

gh api --paginate 'user/repos?per_page=100&affiliation=owner,organization_member' \
  --jq '.[] | select(.private == false and .archived == false and .disabled == false) | .full_name' \
  | LC_ALL=C sort -f
```

To preview exactly what the workflow will write, run the *Fetch repositories* step body from the
workflow file in a scratch shell (set `OUTPUT_FILE`, `OUTPUT_FORMAT`, `GH_TOKEN`, `GITHUB_OUTPUT`).

## Troubleshooting

<details>
<summary><b>The workflow fails with “Could not list repositories”</b></summary>

The token is invalid, expired, or lacks access. Check that the secret exists, has not expired, and
that a fine‑grained token has `Metadata: Read` plus *All repositories* access. For organizations,
make sure the token was approved by an organization owner.
</details>

<details>
<summary><b>The list is empty</b></summary>

The run fails deliberately instead of committing an empty file. Usual causes: `AFFILIATION` is too
restrictive, `EXCLUDE_REPOS` excludes everything, or the token only sees repositories you were
invited to as a collaborator (add `collaborator` to `AFFILIATION`).
</details>

<details>
<summary><b>Organization repositories are missing</b></summary>

Add the `read:org` scope to a classic token (or grant organization access to a fine‑grained one) and
keep `organization_member` in `AFFILIATION`. Repositories you are not a member of stay invisible by
design.
</details>

<details>
<summary><b>Push rejected / “permission denied”</b></summary>

Enable `Settings → Actions → General → Workflow permissions → Read and write permissions`, and make
sure the token has `Contents: Read and write` on this repository. If the default branch is protected,
allow the `github-actions[bot]` actor to bypass the ruleset or push directly.
</details>

<details>
<summary><b>Nothing gets committed</b></summary>

That is the idempotency guard at work: `git diff --cached --quiet` exits early when the list is
unchanged. Check the log line `No changes in the repository list.` — or run with `dry_run` to see
the generated content without committing.
</details>

<details>
<summary><b>The list renders as one long paragraph</b></summary>

Keep `HARD_LINE_BREAKS: "true"` (default), or switch `OUTPUT_FORMAT` to `bullets` / `links`, which
GitHub renders as a proper list.
</details>

<details>
<summary><b>Repositories appear in an unexpected order</b></summary>

Sorting is case‑insensitive by owner and then by name (`LC_ALL=C sort -f`), so `Zeta` comes after
`alpha`. Change the `sort` flags in the *Fetch repositories* step if you prefer raw ASCII ordering.
</details>

## Security notes

- The token is only referenced through `secrets.*`, never echoed; the workflow runs with
  `permissions: contents: write` and nothing else.
- Use a **dedicated** token with an expiration date, and rotate it when it expires.
- Commits made with a personal access token do **not** trigger other workflows — a deliberate side
  effect that keeps the loop quiet.
- Prefer a fine‑grained token limited to `Metadata: Read` + `Contents: Read and write` on this
  repository when you only need public repositories.
